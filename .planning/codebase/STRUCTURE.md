## Directory Purposes

**`src/`:**
- Purpose: Root directory for all TypeScript, React, and CSS source code compiled by Vite.
- Contains: Application entry point (`main.tsx`), root container component (`App.tsx`), global stylesheet (`index.css`), and two subdirectories (`components/` and `lib/`).
- Key files: `src/App.tsx`, `src/main.tsx`, `src/index.css`

**`src/components/`:**
- Purpose: Houses large, interactive visual studio modules (maps and 3D/2.5D viewports).
- Contains: React `.tsx` components that manage canvas/SVG refs, pointer interactions, and floating HUD overlays.
- Key files: `src/components/OsmImporter.tsx`, `src/components/ThreeTerrainViewer.tsx`, `src/components/ContourViewer.tsx`

**`src/lib/`:**
- Purpose: Houses framework-agnostic domain logic, geometric algorithms, external API clients, and binary/text CAD file generators.
- Contains: Pure `.ts` modules with exported interfaces and functions (no React components or JSX).
- Key files: `src/lib/ogucService.ts`, `src/lib/satelliteService.ts`, `src/lib/exportService.ts`, `src/lib/meshProcessor.ts`, `src/lib/SunPosition.ts`, `src/lib/templates.ts`

**`Implementation Plans/` & `handoffs/`:**
- Purpose: Store architectural planning documents, Chilean OGUC regulatory iteration specs, and session handoff logs.
- Contains: Markdown (`.md`) documentation files.
- Key files: `Implementation Plans/implementation_plan.md`, `Implementation Plans/implementation_plan_2.md`, `handoffs/20260512_handoff_geo_arc.md`

## Key File Locations

**Entry Points:**
- `index.html`: Browser HTML shell; loads `/src/main.tsx`.
- `src/main.tsx`: Mounts `<App />` to `#root` and imports `src/index.css`.
- `src/App.tsx`: Main application shell, state container, sidebar controls, and `.geoarc` project import/export handlers.

**Configuration:**
- `package.json`: Defines scripts (`dev`, `build`, `preview`, `clean`, `lint`) and dependencies (`react`, `three`, `d3`, `leaflet`, `fflate`, `fast-png`, `@tailwindcss/vite`).
- `vite.config.ts`: Defines Vite plugins (`react()`, `tailwindcss()`, `overpassProxyPlugin()`), `@` alias resolution, and dev server middleware (`/api/overpass`).
- `tsconfig.json`: Configures TypeScript (`ES2022`, `bundler` module resolution, `react-jsx`, `@/*` path mapping).
- `src/index.css`: Configures Tailwind v4 `@theme` design tokens (`bg-base`, `bg-surface`, `bg-elevated`, `text-main`, `accent`, etc.) and `:root` / `:root[data-theme="dark"]` color palettes.

**Core Logic:**
- `src/lib/ogucService.ts`: Chilean OGUC regulatory engine (`computeOgucModel`, `insetPolygonBisector`, `classifyEdgeOrientation`, `clipWayToBBox`) and OpenStreetMap layer fetcher (`fetchOsmLayersForBBox`, `normalizeOsmElementsToGeom`).
- `src/lib/satelliteService.ts`: High-resolution satellite orthophoto tile downloader, canvas stitcher/cropper, and `.jgw` Worldfile generator (`fetchSatelliteOrthophoto`).
- `src/lib/exportService.ts`: Metric Three.js scene constructor (`buildThreeSceneFromMeshData`), `.glb` exporter (`exportToGlb`), and `.obj` + `.mtl` + `.jpg` + `.jgw` ZIP packager (`exportToObjZip`).
- `src/lib/meshProcessor.ts`: Defines the central `MeshData` interface and `processMeshFile` for converting `.ply` / `.fbx` 3D meshes into smoothed elevation grids.
- `src/lib/SunPosition.ts`: Solar position calculator (`getSunPosition`) returning `{ elevation, azimuth }`.
- `src/components/OsmImporter.tsx`: Interactive Leaflet map (`MapDrawController`), polygon metrics calculator (`calculatePolygonMetrics`), and AWS Terrarium DEM + OSM + Satellite extraction pipeline (`extractOsmData`).
- `src/components/ThreeTerrainViewer.tsx`: WebGL Three.js viewport, 3D Heliodon dome renderer, 3D OGUC envelope/rasante renderer, and raycasted 3D lot drawing.
- `src/components/ContourViewer.tsx`: D3 contour generator, 2D/2.5D SVG matrix projector (`getMatrix`, `projectPoint`, `screenToGrid`), solar raymarcher (`getSolarShadowPolygon`), and `.dxf` / `.stl` exporters (`handleExportDXF`, `handleExportSTL`).

**Testing:**
- Not detected: No automated test runner (`vitest`/`jest`) or `*.test.ts` / `*.spec.ts` files exist in the repository. Static verification is performed via `npm run lint` (`tsc --noEmit`) and `npm run build`.

## Naming Conventions

**Files:**
- **React Components (`src/components/`, `src/App.tsx`):** Use `PascalCase.tsx` matching the default exported component name (e.g., `OsmImporter.tsx`, `ThreeTerrainViewer.tsx`, `ContourViewer.tsx`).
- **Service & Domain Modules (`src/lib/`):** Use `camelCase.ts` with a `*Service.ts` or `*Processor.ts` suffix for multi-function modules (`ogucService.ts`, `satelliteService.ts`, `exportService.ts`, `meshProcessor.ts`). Note: `SunPosition.ts` uses `PascalCase.ts` for historical reasons; prefer `camelCase.ts` for new modules in `src/lib/`.
- **Types & Interfaces:** Use `PascalCase` (`MeshData`, `OgucParams`, `OgucComputedModel`, `VolumeTier`, `RasantePlane`, `SatelliteResult`, `PolygonMetrics`, `AnalysisMode`, `SelectionMode`).

**Directories:**
- Source subdirectories under `src/` use lowercase plural nouns (`src/components/`, `src/lib/`).

## Where to Add New Code

**New Analysis Mode or Regulatory Rule (e.g., PRC / Cabida / Wind / Slope Analysis):**
- Pure mathematical/geometric calculation and typed interfaces: `src/lib/` (extend `src/lib/ogucService.ts` for OGUC rules, or create `src/lib/<domain>Service.ts` for a new domain).
- Mode selector state and sidebar parameter inputs: `src/App.tsx` (extend `export type AnalysisMode` at `src/App.tsx:40`, add parameter states, and include them in `handleExportGeoarc` / `handleImportGeoarc` at `src/App.tsx:330-449`).
- 3D WebGL visualization overlay: `src/components/ThreeTerrainViewer.tsx` (inside the dynamic overlay `useEffect` at `src/components/ThreeTerrainViewer.tsx:668` and bottom-left HUD at `src/components/ThreeTerrainViewer.tsx:1313`).
- 2D/2.5D SVG technical visualization and legend: `src/components/ContourViewer.tsx` (inside `<g ref={zoomGroupRef}>` at `src/components/ContourViewer.tsx:1312` and the bottom-left legend panel at `src/components/ContourViewer.tsx:2017`).

**New CAD / 3D / GIS Export Format:**
- Implementation: `src/lib/exportService.ts` (use `buildThreeSceneFromMeshData` for 3D formats or consume `MeshData` directly, and trigger downloads via `triggerBrowserDownload`).
- UI Trigger: Add quick-export button in the viewport header bar of `src/App.tsx` (`src/App.tsx:969-1000`) or the floating export toolbar in `src/components/ContourViewer.tsx` (`src/components/ContourViewer.tsx:1236-1246`).

**New Geospatial Data Source or External API:**
- Client fetcher & data normalizer: `src/lib/` (e.g., `src/lib/satelliteService.ts` or `src/lib/ogucService.ts`).
- Extraction orchestration during terrain import: `extractOsmData` in `src/components/OsmImporter.tsx` (`src/components/OsmImporter.tsx:582-762`) and `MeshData` interface in `src/lib/meshProcessor.ts` (`src/lib/meshProcessor.ts:5-18`).
- CORS / Upstream Proxy (if required by upstream headers): Add a Vite server middleware plugin in `vite.config.ts` following `overpassProxyPlugin()` (`vite.config.ts:6-104`).

**New UI Component:**
- Implementation: Create `src/components/<ComponentName>.tsx` using Tailwind v4 theme utility classes (`bg-bg-surface`, `bg-bg-elevated`, `border-border-main`, `text-text-main`, `text-text-faded`, `text-accent`) so light and dark themes work automatically.

**Utilities:**
- Shared geometric, coordinate-conversion, or formatting helpers: Place in `src/lib/` and export named functions.
